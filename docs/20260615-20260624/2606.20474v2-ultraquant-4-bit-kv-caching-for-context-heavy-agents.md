## 摘要
上下文密集型任务给键值（KV）缓存带来了异常压力：长前缀在多个短轮次中被复用，而并发性决定了服务系统能否保持GPU的利用率。我们针对此场景研究了4位KV缓存压缩，使用TurboQuant风格的旋转和码本量化作为质量锚点，以vLLM FP8 KV缓存作为部署锚点。我们报告了三项贡献。首先，我们将4位KV缓存框架用于多轮代理工作负载，其中任务质量、缓存驻留时间和服务吞吐量必须联合衡量。其次，我们描述了使4位路径稳健所需的实际设计选择，包括不对称的K/V处理、Walsh-Hadamard旋转、QJL移除和块缩放变体。第三，我们展示了在AMD GPU上的服务优化，包括优化的解码注意力内核和UltraQuant——一种使用FP8查询、FP4 KV张量、UE8M0组缩放以及CDNA4上原生scaled-MFMA支持的FP4近似路径。在一个长上下文、多轮代理工作负载中，UltraQuant在缓存压力大的后期轮次中将P50首次令牌延迟降低了3.47倍（所有轮次平均降低2.3倍），并将输出吞吐量比FP8 KV基线提高了1.63倍。

## Abstract
Context-heavy agents place unusual pressure on the key-value (KV) cache: long prefixes are reused across many short turns, while concurrency determines whether the serving system can keep GPUs utilized. We study 4-bit KV-cache compression for this setting, using TurboQuant-style rotation and codebook quantization as a quality anchor and vLLM FP8 KV caching as the deployment anchor. We report three contributions. First, we frame 4-bit KV caching around multi-round agent workloads where task quality, cache residency, and serving throughput must be measured jointly. Second, we describe the practical design choices needed to make the 4-bit path robust, including asymmetric K/V treatment, Walsh-Hadamard rotation, QJL removal, and block-scale variants. Third, we present serving optimizations on AMD GPUs, including optimized decode-attention kernels and UltraQuant, an FP4 approximation path that uses FP8 queries, FP4 KV tensors, UE8M0 group scales, and native scaled-MFMA support on CDNA4. On a long-context, multi-turn agentic workload, UltraQuant cuts P50 time-to-first-token by 3.47x in the cache-pressured late rounds (2.3x across all rounds) and raises output throughput by 1.63x over the FP8 KV baseline.

# 论文详细中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：上下文密集型智能体（如浏览网页、操作仓库、软件开发等）需要长时间运行的记忆，导致 KV 缓存随上下文长度线性增长，成为高带宽内存（HBM）的首要消费者。传统 FP8 KV 缓存（如 vLLM 中的实现）在面临长用户前缀和高并发时，经常发生缓存逐出，重新预填充增加延迟。
- **目标**：在保持任务质量的同时，通过 4 位 KV 缓存压缩增加有用前缀的驻留量，从而提升服务吞吐量和降低首令牌延迟（TTFT），并解决 4 位量化带来的额外解量化开销问题。

## 2. 方法论

### 2.1 核心思想
- 以 TurboQuant 风格的旋转+码本量化作为质量锚点，但替代为硬件原生 FP4 近似路径 (UltraQuant)，使解量化融合进矩阵核心指令，避免软件查找表（LUT）带来的不规则访问开销。
- 采用不对称 K/V 处理（键和值使用不同量化策略），Walsh–Hadamard 旋转扩散离群能量，块缩放变体，以及一个全局常数优化的缩放因子。

### 2.2 关键技术细节
- **Ultra-TQ**：保持 TurboQuant 码本表示，但优化布局、查找表和 MFMA 调度，以及为每模型校准质心（Lloyd–Max 算法）。校准仅在约 10% 的高均方误差层上进行。
- **UltraQuant**：
  - 缓存布局：每个组（32 个通道）编码为 32 个 FP4 E2M1 码（每字节 2 个码）加上 1 个 UE8M0 尺度字节，共 4.25 位/元素。
  - 解量化规则：`value = code × 2^{scale}`，其中 `scale = byte - 127`（即指数移位），直接通过 CDNA4 的 `MFMA_SCALE_F32_*_F8F6F4` 指令原生执行。
  - 全局常数优化缩放：每个 32 通道组使用 `s = c * m`，其中 `m = max_i |x_i|`，`c` 为全局常数（通过单次前向传播在少量校准数据上优化得到，部署为 0.156）。
  - 无需逐 Token 的 ℓ2 归一化：块缩放已吸收所有幅度变化。
  - 边界层保护：前 2 层和后 2 层注意力保留 BF16 KV 缓存。
- **算法流程**：旋转键（对查询也旋转并转换为 FP8），划分 32 通道组，每组计算最大绝对值后计算 UE8M0 指数，再将每个元素四舍五入到最近 FP4 码值；解码时加载码值和尺度，通过缩放 MFMA 执行 QK 和 PV 乘积。

## 6. 主要结论与发现

- **服务性能**：在代理工作负载中，UltraQuant 相比 FP8 KV 基线，在缓存压力大的后期轮次将 P50 TTFT 降低了 3.47 倍，全部轮次平均降低 2.3 倍；输出吞吐量提升 1.63 倍。
- **延迟**：UltraQuant 的每令牌延迟（TPOT）与原生 FP8 路径几乎相同（1.40× BF16 vs FP8 1.37×），远优于 Ultra-TQ（1.58×）和开源 TurboQuant（5.56×）。
- **准确度**：非均匀表现——在 MATH500 上近无损，在 GPQA 和 LCB-128K 上略有下降，但在 AIME25 上下降显著（-10~-13pp）。论文指出这是真实局限而非掩盖。
- **关键设计**：块缩放（per-block absmax）是恢复准确度的主要杠杆，码本（校准 vs 均匀）影响不大；全局常数 c=0.156 在 MSE 上最优，且比 FP8 基线高 4.4pp，而 c 过大或过小均导致退化。

## 7. 优点

- **系统性方法论**：联合考虑质量、缓存驻留、吞吐量和交互性，而非单纯离线压缩。
- **硬件与算法协同**：利用 CDNA4 的原生 FP4+UE8M0 路径，消除解量化开销，使 4 位部署达到 FP8 硬件路径的吞吐量。
- **实用细节丰富**：边界层保护、旋转+块缩放替代逐 Token 归一化、全局常数仅需一次校准且跨模型迁移。
- **优化阶梯清晰**：从优化的 TurboQuant 内核到 FP4 路径，逐步降低开销。
- **消融实验覆盖关键选择**：块缩放 vs 逐 Token 归一化、码本 vs 固定网格、全局常数取值的敏感性，提供了有意义的设计洞察。

## 8. 不足与局限

- **准确度短板**：在 AIME25 等复杂推理基准上出现显著准确度下降（-13pp），论文承认但未提供缓解方案。
- **实验覆盖有限**：
  - 服务性能仅用一款模型（MiniMax-M2.5），未检验跨模型泛化。
  - 准确度仅报告单次运行（无方差），无法评估统计显著性。
  - 未与更多 4 位量化方法（如 KIVI、KVQuant、QJL 等）横向对比。
- **全局常数非最优**：固定单一常数 c=0.156 对所有层和头部，可能存在逐层更优的常数（论文自身提及局限性 1）。
- **性能优势局限于长上下文**：当上下文长度不足以超过 FP8 的驻留容量时，UltraQuant 的吞吐优势无法体现（局限性 2）。与 Ultra-TQ 比较时优势恒成立，但论文主要亮点是与 FP8 比较。
- **校准步骤复杂**：Ultra-TQ 的校准仅用于 10% 层且收益小，而 UltraQuant 的常数校准虽小但需要一次额外前向传播（轻微部署负担）。
