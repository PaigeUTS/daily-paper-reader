## 摘要
上下文密集型智能体对键值（KV）缓存施加了异常压力：长前缀在许多短交互轮次中被重用，而并发性决定了服务系统能否保持GPU利用率。我们针对这一场景研究了4位KV缓存压缩，采用TurboQuant风格的旋转和码本量化作为质量锚点，vLLM FP8 KV缓存作为部署锚点。我们报告了三项贡献。首先，我们围绕多轮智能体工作负载构建了4位KV缓存框架，其中任务质量、缓存驻留时间和服务吞吐量必须联合衡量。其次，我们描述了使4位路径鲁棒所需的实际设计选择，包括非对称K/V处理、Walsh-Hadamard旋转、QJL移除和块级缩放变体。第三，我们展示了AMD GPU上的服务优化，包括优化的解码注意力核和UltraQuant，这是一种使用FP8查询、FP4 KV张量、UE8M0组缩放以及CDNA4上原生缩放MFMA支持的FP4近似路径。在长上下文、多轮智能体工作负载上，在缓存压力大的后期轮次，UltraQuant将P50首次令牌生成时间减少了3.47倍（所有轮次平均2.3倍），并将输出吞吐量相比FP8 KV基线提升了1.63倍。

## Abstract
Context-heavy agents place unusual pressure on the key-value (KV) cache: long prefixes are reused across many short turns, while concurrency determines whether the serving system can keep GPUs utilized. We study 4-bit KV-cache compression for this setting, using TurboQuant-style rotation and codebook quantization as a quality anchor and vLLM FP8 KV caching as the deployment anchor. We report three contributions. First, we frame 4-bit KV caching around multi-round agent workloads where task quality, cache residency, and serving throughput must be measured jointly. Second, we describe the practical design choices needed to make the 4-bit path robust, including asymmetric K/V treatment, Walsh-Hadamard rotation, QJL removal, and block-scale variants. Third, we present serving optimizations on AMD GPUs, including optimized decode-attention kernels and UltraQuant, an FP4 approximation path that uses FP8 queries, FP4 KV tensors, UE8M0 group scales, and native scaled-MFMA support on CDNA4. On a long-context, multi-turn agentic workload, UltraQuant cuts P50 time-to-first-token by 3.47x in the cache-pressured late rounds (2.3x across all rounds) and raises output throughput by 1.63x over the FP8 KV baseline.

- **研究动机**：为应对多轮智能体场景下的极端内存压力，需要更激进的压缩（4-bit），同时保证任务准确性和系统服务效率。作者提出以 TurboQuant（旋转+码本量化）作为质量锚点，以 vLLM 的 FP8 KV 缓存作为部署锚点，研究 4-bit 缓存的实际部署方案。
- **整体含义**：本文从端到端服务角度评估 4-bit 量化，强调不仅要看压缩率，还要看缓存驻留（cache residency）、吞吐和交互性。通过硬件友好的 FP4 近似路径（UltraQuant）和 AMD CDNA4 矩阵核原生支持，在服务性能上接近 FP8 甚至更优。

### 2. 方法论

- **核心思想**：采用 **TurboQuant 风格的旋转+码本量化**作为质量参考，但将其从纯码本方案改造为硬件原生格式。论文提出了两条路径：
  1. **Ultra-TurboQuant (Ultra-TQ)**：优化 TurboQuant 的实现，通过校准质心（Lloyd-Max）、改进布局和核调度，提升质量。
  2. **UltraQuant**：舍弃码本，采用 **FP4 E2M1 微张量 + UE8M0 组缩放**，使去量化直接由 CDNA4 矩阵核（scaled-MFMA）完成，避免软件查找表。
- **关键技术细节**：
  - **非对称 K/V 处理**：Keys 经过 Hadamard 旋转以分布异常值，Values 不旋转。
  - **Walsh-Hadamard 旋转**：将键特征向量旋转到接近高斯分布，使标量量化更有效。
  - **QJL 移除**：论文移除了 TurboQuant 中的 QJL（量化 JL 变换）组件，简化设计。
  - **块缩放（Block-Scale）**：每个 32-通道组使用一个 UE8M0 指数作为缩放因子 s = c·m，其中 m 是组内绝对值最大值，c 是全局常数（0.156）。缩放使得 FP4 网格拟合旋转后分布。
  - **常量优化（ConstOpt）**：全局常数 c 通过最小化 MSE 离线校准，一次选定即适用于所有模型（仅依赖头维度 d）。
  - **去量化形式**：value = code × 2^{byte-127}，通过 MFMA 指令中的缩放操作直接完成。
  - **边界层保护**：第一和最后两层注意力保留 BF16，避免极端退化。
- **算法流程（文字说明）**：编码时，对 K 施加旋转，将 K/V 分成 32-通道组，每组计算 m 并编码为 FP4（映射到 E2M1 最近点），同时存储 UE8M0 缩放字节。解码时，Q 先旋转并量化为 FP8，然后 QK 乘积通过 FP8×FP4 缩放 MFMA 指令完成，PV 路径类似。

### 7. 优点

- **端到端服务视角**：联合评估准确性、缓存驻留和吞吐，而非仅压缩率。

- **充分的消融实验**：验证了 per-block 缩放、全局常数选择等关键设计。
