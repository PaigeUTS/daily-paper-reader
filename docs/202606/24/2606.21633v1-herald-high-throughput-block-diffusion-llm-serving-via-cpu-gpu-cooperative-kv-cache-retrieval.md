## 摘要
扩散LLM（dLLM）通过每次前向传播生成多个令牌，相比自回归解码提高了GPU利用率，但其KV缓存仍随上下文线性增长，限制了长上下文下的吞吐量。将KV缓存卸载到主机DRAM可缓解这种内存压力，但有限的PCIe带宽要求仅召回KV条目的稀疏子集。在块dLLM中，相关KV条目在块内的去噪步骤中保持一致，通过一次性识别top-k条目并在所有去噪步骤中重复使用，可实现高精度选择。这一特性对于卸载而言颇具吸引力，因为它将选择开销分摊到整个块上，但需要在整个KV缓存上进行精确注意力计算，这在卸载情况下成本过高。我们提出HERALD，一种用于块dLLM的KV卸载系统，通过两个机会解决了这一问题：将所需的选择计算量降低一个块大小的因子，并使选择能够与去噪重叠。在三个块dLLM和五个长上下文任务上，HERALD在5-10%的KV预算下实现了近乎无损的精度，每块延迟最多降低1.59倍，吞吐量比纯GPU推理高出2.47倍，且加速比随上下文长度增长。

## Abstract
Diffusion LLMs (dLLMs) improve GPU utilization over autoregressive decoding by generating multiple tokens per forward pass, but their KV cache still grows linearly with context, limiting throughput at long contexts. KV cache offloading to host DRAM alleviates this memory pressure, but the limited PCIe bandwidth necessitates recalling only a sparse subset of KV entries. In block dLLMs, the relevant KV entries remain consistent across denoising steps within a block, enabling high-accuracy selection by identifying the top-k entries once and reusing them throughout all denoising steps. This property appears attractive for offloading as it amortizes the selection overhead across the entire block, but it requires exact attention over the full KV cache, which is too expensive under offloading. We present HERALD, a KV offloading system for block dLLMs that resolves this through two opportunities that reduce the required selection compute by a factor of the block size and enable selection to be overlapped with denoising. Across three block dLLMs and five long context tasks, HERALD achieves near-lossless accuracy at 5-10% KV budget and up to 1.59x lower per block latency and 2.47x higher throughput over GPU-only inference, with speedups growing with context length.

# HERALD 论文中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：大型语言模型（LLM）推理中，自回归解码每次只生成一个token，GPU利用率低；扩散LLM（dLLM）通过每次前向生成多个token来提高利用率。其中块扩散LLM（Block dLLM）成为主流，将输出划分为固定大小的块，在每个块内进行多次去噪步骤并行解码。
- **问题**：尽管块dLLM提高了算术强度，但KV缓存仍随上下文长度线性增长，占用大量GPU显存，限制了批量大小和系统吞吐量。将KV缓存卸载到主机DRAM能缓解显存压力，但PCIe带宽远低于GPU显存带宽，完整传输KV缓存成本过高。
- **关键挑战**：现有KV卸载方法在自回归LLM中仅召回稀疏的子集，但块dLLM需要在整个KV缓存上进行精确注意力计算来选择top-k条目，这在卸载场景下面临两个障碍：
  - **硬件映射挑战**：全KV缓存位于CPU内存，在CPU上计算需要处理B个查询（块大小），CPU缺乏矩阵乘法单元导致延迟过高；在GPU上计算则需要先传输全量KV，PCIe传输成为瓶颈。
  - **依赖挑战**：下一个块的top-k选择依赖于当前块最终确定的token，因此选择必须在当前块去噪完成后才能开始，无法隐藏延迟。

## 2. 方法论：核心思想与关键技术细节

### 核心思想
HERALD利用块dLLM的两大结构特性，实现CPU-GPU协同的KV缓存检索，将选择计算量减少块大小倍，并使选择与去噪完全重叠。

### 关键技术细节

1. **机会1：单一中心[MASK]查询足以进行块级选择**
   - 在块的第一步去噪时，所有B个位置都是[MASK] token，它们共享相同的嵌入，仅因RoPE位置编码不同而有所差异。
   - 选择块中心位置（`⌊B/2⌋`）的[MASK] token作为单一查询，其相对偏移偏差最小，能保留约84%的top-k召回率（B=32时）。
   - 将CPU注意力计算量减少B倍（例如B=32时加速22–24倍），使CPU能够在不延迟的情况下处理全KV精确选择。

2. **机会2：步0的logits提供免费的语义代理**
   - 在块去噪的第0步，模型对所有B个位置产生logits；传统方法仅保留高置信度位置，丢弃其余logits。
   - HERALD对全部B个位置取argmax，生成当前块的草稿（draft）以及对应的KV缓存。该草稿作为下一个块选择时的前缀上下文，即使不完全准确，也足以指导top-k选择。
   - 此举打破了数据依赖：当前块去噪尚未完成时，即可开始下一个块的选择，实现重叠。

3. **系统设计：双流解码流水线 + 双缓冲稀疏KV池**
   - **主流（Main Stream）**：GPU上执行当前块的所有去噪步骤（步0到步T）。
   - **检索流（Retrieval Stream）**：CPU上执行下一个块的KV选择，同时GPU处理检索流中所需的FFN计算。
   - **双缓冲KV池**：GPU维护两个稀疏KV池，一个用于当前块去噪，另一个由检索流填充下一个块的top-k KV条目。
   - **流水线执行**：
     - 预填阶段：处理提示，将KV逐层异步拷贝到CPU，并对提示KV进行top-k选择作为第一个块的稀疏池。
     - 解码阶段：对于块N，首先执行步0与草稿融合前向（一次性处理2B个token，一组去噪，一组生成草稿KV）。然后主流继续剩余去噪步骤，同时检索流CPU对全KV执行中心[MASK]查询的精确注意力+top-k选择，GPU执行检索流的FFN；选择出的top-k KV条目通过DMA异步传输到GPU的空闲池中。
     - 当块N去噪完成时，块N+1的稀疏KV池已就绪，池指针交换，进入下一个块。

4. **优化的CPU内核：融合注意力与top-k选择**
   - 以单个KV头为单位流式处理，缓存所有查询头的注意力分数，同时累积FlashAttention的在线softmax统计。
   - 利用已计算的统计聚合各查询头的分数为一个重要性向量，只需一次top-k堆遍历即可选出该KV头中最重要的K个位置，避免了对每个查询头分别执行top-k。
   - 注意力输出立即传输给GPU进行FFN，选中的稀疏KV条目通过异步DMA传输与下一层选择重叠。
