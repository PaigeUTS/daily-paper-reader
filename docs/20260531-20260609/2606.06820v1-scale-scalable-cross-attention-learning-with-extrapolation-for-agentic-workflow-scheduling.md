## 摘要
大型语言模型（LLM）智能体系统将复杂任务分解为工作流有向无环图（DAG），其基本任务需要在异构集群上进行调度。现有的深度强化学习（DRL）调度器与固定集群规模绑定，当服务器数量发生变化时需要重新训练。我们提出了SCALE（可扩展的跨注意力学习与外推方法），这是一种无需微调即可泛化到未见过的集群规模的DRL调度器。SCALE采用跨注意力指针网络，其中任务特征查询服务器特征，因此该架构天然支持任意数量的服务器。然而，我们观察到仅靠置换不变架构无法保证在新规模下的良好性能——随着服务器数量增长，注意力特征会出现分布偏移。为解决这一问题，我们引入了结构化表示正则化（SRR）：一种去相关损失结合对标准正态分布的KL惩罚，使得特征统计量在不同输入规模下保持稳定。在16个节点上训练并直接测试于32和48个节点时，与没有SRR的相同架构相比，SCALE在N=48时将平均响应时间降低了8.9%，证实了显式正则化对于弥合规模泛化差距的必要性。

## Abstract
Agentic Large Language Model (LLM) systems decompose complex tasks into workflow Directed Acyclic Graphs (DAGs) whose primitives must be scheduled on heterogeneous clusters. Existing deep reinforcement learning (DRL) schedulers are tied to a fixed cluster size and require retraining whenever the number of servers changes. We propose SCALE (Scalable Cross-Attention Learning with Extrapolation), a DRL scheduler that generalizes to unseen cluster scales without fine-tuning. SCALE employs a cross-attention pointer network where task features query against server features, so the architecture accepts any number of servers by construction. We observe, however, that permutation-invariant architecture alone does not guarantee good performance at new scales - the attention feature undergoes distribution shift as the server count grows. To counter this, we introduce Structured Representation Regularization (SRR): a decorrelation loss combined with a KL penalty toward the standard normal, which keeps feature statistics stable regardless of input size. Trained on 16 nodes and tested directly on 32 and 48 nodes, SCALE reduces average response time by 8.9% at N=48 relative to the same architecture without SRR, confirming that explicit regularization is necessary to close the scale-generalization gap.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：智能体LLM系统（如AutoGPT、LangGraph）将复杂任务分解为有向无环图（DAG）的工作流，其中每个节点是一个基本操作（工具调用、推理步骤），需要在异构集群上调度。这些操作的计算需求、内存需求差异大，且工作流动态到达、执行路径实时决定，给调度带来挑战。
- **现有方法不足**：经典的列表调度算法（如HEFT）要求处理器集合固定且已知；现有的深度强化学习（DRL）调度器（如DeepRM、Decima）将集群大小编码到网络结构中，一旦服务器数量变化（如自动扩缩容、机器故障）就必须重新训练，无法泛化到不同规模。
- **研究目标**：设计一个DRL调度器，能在小集群（如16节点）上训练后，直接部署到大规模集群（32、48节点）上，无需微调，同时保持调度质量。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
通过**跨注意力指针网络**使模型天然接受任意数量服务器，并引入**结构化表示正则化（SRR）** 稳定注意力特征的统计分布，从而弥合规模泛化差距。

### 2.2 关键技术细节
1. **两级调度架构**：
   - 第一级（确定性启发式）: 从就绪任务中选择关键路径最长的一个任务 `v*`。
   - 第二级（RL Agent）: 对选中的任务，策略网络选择一个服务器分配。

2. **跨注意力指针网络**：
   - **嵌入层**：任务特征 `ϕ` (5维) 通过MLP `g_p` 映射为查询向量 `q`；每个服务器特征 `ψ_j` (5维) 通过共享MLP `g_s` 映射为键/值向量 `z_j`。
   - **L层跨注意力**：每层以当前任务查询 `q` 为query，所有服务器嵌入为key-value，经过多头注意力 + FFN + 残差层归一化，得到最终注意力特征 `f`。
   - **Actor（指针网络）**：以 `f` 乘以投影矩阵 `W_q` 作为query，每个服务器嵌入乘以 `W_k` 作为key，计算点积得分，经softmax得到选择各服务器的概率。输出维度自动等于当前服务器数N。
   - **Critic**：仅使用 `f` 通过三层MLP估计状态价值，避免对N的隐式依赖。

3. **结构化表示正则化（SRR）**：
   - **去相关损失 `L_c`**：惩罚mini-batch中注意力特征 `f` 的经验协方差矩阵的非对角元素总和，推动维度间独立。
   - **分布约束损失 `L_d`**：对每个维度计算与标准正态N(0,1)的KL散度，迫使边际分布接近标准正态。
   - 总训练损失：`L = L_π + λ1 L_c + λ2 L_d`，其中 `L_π` 是PPO策略损失（含价值损失和熵）。
   - 额外策略：在训练初期（epoch 10开始）线性warmup正则化项至epoch 60，避免干扰初始策略学习。

## 3. 实验设计

### 3.1 仿真场景与数据集
- **集群**：三类异构服务器（Small/Medium/Large，容量比例1:2:4，内存8/32/80GB），基础规模N=16，扩展至N=32、48按比例增加各类型数量（2:5:1）。
- **工作流**：随机生成DAG，节点数3~8（均匀分布）。计算需求服从截断正态`N(10, 3²)`，内存需求`N(16, 8²)`，数据体积`N(0.5, 0.2²)` GB。到达过程为泊松流，到达率随规模线性增长（λ=1.0,2.0,3.0分别对应16,32,48节点）以保持负载压力。

## 6. 主要结论与发现

- **SCALE成功实现零样本规模泛化**：在16节点训练后直接部署到32和48节点，响应时间较无SRR的CrossAttn分别降低2.3%（5.70→5.57）和8.9%（6.83→6.22）。在48节点时，8.9%的改进具有实际意义。
- **仅靠置换不变架构不足**：CrossAttn（无SRR）在规模增大时响应时间明显劣化（6.83s vs 6.22s），证明需要显式特征正则化。
- **SRR稳定了特征分布**：表5显示SCALE的注意力特征协方差非对角项始终<0.05，而CrossAttn随规模漂移（0.27→0.09），且SCALE的KL散度更稳定。
- **性能权衡**：SCALE在训练规模（N=16）上完成更多任务（8.37 vs 8.10）但响应时间略高于PPO（4.58s vs 4.37s），符合正则化牺牲分布内性能换取稳健性的预期。

## 7. 优点

- **方法论创新**：首次系统揭示跨注意力架构本身不足以保证规模泛化，并提出SRR显式正则化解法。
- **实用性**：训练一次即可适应弹性集群变化，避免昂贵重训练，适合云原生环境自动扩缩容场景。
- **轻量级实现**：使用CPU即可完成训练，模型参数少（嵌入维度16，2层注意力），推理开销低。
- **分析深入**：通过特征协方差和KL散度直接观测正则化效果，提供了理论支撑。
- **实验设计清晰**：对比基线选择合理，消融实验直接凸显SRR贡献，且报告了标准差，体现统计可靠性。

## 8. 不足与局限

- **规模外推范围有限**：仅测试至48节点（3倍），未验证128+等更大规模是否保持效果（注意力softmax分母变大可能导致概率扁平化问题加剧）。
- **集群构成单一**：实验中服务器类型比例固定（小:中:大 ≈ 2:5:1），未评估不同类型比例或完全同构集群下的泛化能力。
- **工作流多样性不足**：DAG节点数仅3-8，且随机生成；真实智能体工作流可能有更复杂依赖（如条件分支、循环）、更长链、或更宽扇出，实验未覆盖。
- **第一级调度器未学习**：使用启发式选择任务，未与第二级联合优化，可能成为瓶颈。
- **物理部署缺失**：仅仿真，未在真实集群（如Kubernetes + LangGraph）上验证实际延迟和资源效率。
- **分布内性能轻微退化**：SCALE在训练规模（16节点）上的响应时间不如PPO（4.58s vs 4.37s），表明放弃了部分分布内最优性。
- **超参数敏感性**：SRR权重（λ1=0.01, λ2=0.001）和warmup策略可能需针对不同场景调整，缺乏鲁棒性讨论。
